Code3D lets you and local coding agents work on the same open project. The App
owns file changes, checks for concurrent edits, and evaluates models. Agents can
read source, make changes, and ask for images, types, or geometry information.
Their observations use the same modeling engine as your view.

## Connect a local agent

1. Open **Connect Agent** at the right of the top bar. If agents already exist,
   use the user-with-gear button beside their pills.
2. Choose a name, keep the suggested local port, and select **Add agent & copy
   prompt**. Paste the prompt into your local agent's current conversation.
3. Keep this Code3D page open. Allow its local-network connection when your
   browser asks.

The prompt gives the agent its private configuration and the required
[Markdown instructions](../../agents.md). Those instructions explain how to start
the local service, get live project context, and work in Code3D.
The agent can connect without restarting its conversation. Its host keeps the
service running for that conversation and closes it when the session ends.

Each agent has its own identity, color, port, and access key. You can connect
several agents to the same project. The page retries while it waits for their
services, so it is fine to copy a prompt before the service starts. If a port is
occupied, change it and copy the updated prompt for that agent.

Configurations belong to this project and persist when you close the dialog or
reload the page. Opening the project reconnects its agents. Only one browser tab
at a time serves a project's agents; another tab reports that the project is
already active elsewhere.

## See where agents are working

Each agent has a pill in the top bar and a colored cursor with a name label in
the editor. These cursors remain separate from your selection. Formatting keeps
them attached to the corresponding source. The relative activity time on the
label tells you how recent a position is; hover for the exact date.

The file explorer also marks each agent's location. If its file is inside a
collapsed folder, the marker appears on the nearest visible parent. Dots dim
while disconnected or until the agent first interacts after the page opens.
**Never connected** in the dialog means that the agent has never made a request,
including across page reloads. The connection indicator at the top right explains
the local connection state on hover.

## Follow an agent

Click an agent's pill to follow it. The mouse-pointer icon marks the active
follow state; click again to stop, or choose another agent to switch.

Following immediately jumps to that agent's latest activity. Subsequent activity
can open a file the agent reads, reveal and focus a folder it lists, or move to
its model selection. Model selections also synchronize the displayed model or
sketch, preview arguments, and any requested camera view or Modeling/Render mode.
Folders scroll into view when necessary.

You can still edit and navigate freely. Following jumps when the agent changes
its target or source; it does not lock your controls. Looking again at an unchanged
model does not repeatedly move your view. If the agent has no current target,
your view stays where it is until the next activity.

## Review what the agent sees

When an agent requests a render, its returned image appears below the controls
at the top right of the Modeling or sketch view. The preview shows the agent's
name, color, and capture time. It is the same image sent to the agent, including
its requested camera angle and render mode.

Click the preview to fill the visualization area and browse the timeline below
it. You can filter by agent, step between images, or use Left/Right, Home, and End
while the timeline is focused. Selecting an older image keeps it in view as new
ones arrive; **Latest** resumes showing the newest image.

The preview's close button hides it until a new image arrives. Render mode hides
the preview while preserving its history. Escape or **Back to live view** closes
the expanded viewer. Your source editor stays available throughout.

The timeline retains the latest 100 renders across this project's agents and
restores them from saved request results after a reload. It records images;
opening one does not restore old code or change the live camera. Agent cursors
continue to show their current positions.

## Changes and concurrent work

Agents read file versions and submit complete source updates. The App checks
those versions before accepting a batch, so an agent working from stale source
must read the latest content and reconcile its changes. This also applies when
several agents edit together.

Saving source and successfully rendering a model are separate outcomes. A model
error can leave an accepted edit in the project, where you and the agent can
inspect and fix it. New code replaces an in-progress compilation. Dependency
installation follows the project's [storage and package settings](../../getting-started/files/).

## Manage access

In **Connect Agent**, copy an initial or updated prompt beneath the relevant
agent, or change its port. The prompt contains a private access key; share it
only with the agent that should work on this project.

**Revoke** removes one agent's access, saved request results, and image history.
**Revoke all** removes every agent for this project. Both stop the page's retries;
the agent's host still owns its local process. Changes already accepted by the
App continue saving. To reconnect a revoked agent, create a new grant and copy
its new prompt.

For the executable workflow and detailed operation reference, start with the
[agent Markdown entry](../../agents.md). For ordinary project use, see
[working in the App](../../getting-started/app/).
