## Describe the parameters

Each `@code3d.param` names a parameter in the function's signature:

- `kind: 'length'` describes a dimension.
- `kind: 'angle'` describes an angle.
- `kind: 'ratio'` describes a dimensionless factor, such as a scale multiplier.
- `kind: 'count'` describes an integer count.
- `kind: 'scalar'` describes a general numeric value without a more specific kind.
- `label` can give the input a readable name.
- `constraints` can supply `min`, `max`, `exclusiveMin`, and `exclusiveMax`.
- `default` describes the value to display when a numeric argument
  is omitted.

For example:

```ts
/** @code3d.param radius {kind: 'length', label: 'Radius', constraints: {min: 1}} */
```

Place the cursor in `spacer(12, 5, 6)` to open its parameter panel. Change an
input and the App writes to the corresponding source value. Normal source
Undo and Redo still apply.

The editor highlights recognized tags, completes configuration fields, and
reports invalid annotations. Put annotations on the callable declaration,
not on a variable that happens to hold a dimension. For overloaded functions,
annotate the overload signatures that should offer tools.

## Describe an omitted argument's default

```ts
/** @code3d.param height {kind: 'length', default: 12} */
function spacer(height = 12) {
  // Build the model using height.
}
```

For `spacer()`, the panel shows `12` as a numeric placeholder. The annotation
describes this display value; the function implementation decides what an
omitted argument actually does. Keep the two consistent. The App reads the
same annotation from source and published `.d.ts` declarations, without
extracting initializer values or applying annotations during ordinary execution.

`default` accepts a finite numeric literal, including zero and negative values,
on a required or optional numeric parameter. A `count` default must be an integer, and
every default must satisfy its parameter's constraints. Expressions such as
`Math.PI` and variable references are not accepted in this static metadata.

A runtime default can preserve a required public signature. Put the annotation
on the overload and the default in its implementation:

```ts
import {circle} from '@code3d/core';

/** @code3d.param radius {kind: 'length', default: 5} */
function makeDisc(radius: number): ReturnType<typeof circle>;
function makeDisc(radius = 5): ReturnType<typeof circle> {
  return circle(radius);
}
```

An incomplete `makeDisc()` call can preview using `5`, while TypeScript still
asks for a radius. Built-in
[dimension-based primitives](../../reference/core/#runtime-defaults-while-editing)
use this behavior too.

An explicit argument keeps its usual display and editing behavior, including
`undefined` or an expression that produces no numeric result; it never falls
back to the annotation default. A parameter without `default` remains blank
when omitted.

## Preview a function with example arguments

Each `@code3d.arguments [...]` supplies one design-time invocation. In the
function's source context, the App lets you switch between real calls and
these candidates. Their values are ordinary TypeScript expressions evaluated
in the function's module scope, with completion from its signature.

These invocations provide preview contexts; they do not replace the function's
normal execution or change its exports. Exporting the function remains an
ordinary choice about reuse by another module.

## What a panel can edit

The active tool's call is underlined in the editor and scrolls into view without
taking focus from the panel. A static caret and word marker retain your source
position when focus moves into the viewport. Parameter, topology, and spatial
tools share this navigation behavior, including newly inserted calls.
Choosing a spatial tool keeps a matching current call or checks the immediately
following transformation. A matching call activates immediately and places the
caret at the expression end, such as `offset()|` or `aroundEdge(1).rotate(25)|`.
The toolbar is available throughout `relate(...)`, including `self.axis`, target
references, and callback whitespace, without activating a tool by default.
Expression panels and reference highlights keep their focus until you choose a
spatial tool, which acts on that relation's `self`. Nested `relate` calls use the
innermost `self`. A callback returning one constraint also supports these tools;
its first added transformation converts the return value to an array.
The start of `self` in a relation also provides this lookup. It does not skip
a different transformation to find a matching call farther ahead. If the call needs
to be added, the caret moves to its insertion gap and the viewport shows the
state immediately before that position. Neither action changes the source until you edit the model.
Tool edits place the caret after the affected call name, before `(`: picking a
vertex focuses `pivotVertex`, while changing rotation angles focuses `rotate`.
Moving the caret into an argument list yourself still highlights its parameter.

The origin is marked by a lime cross with a center dot. A rotation pivot uses
an orange ring with a center dot; an axis reference remains orange. These markers
follow your edit while the model updates, including consecutive drags. Choosing
point rotation shows its pivot before a rotation call is written. Holding Alt
switches to moving that pivot and keeps the same marker.

Controls follow a unique chain of TypeScript definitions to an editable
numeric source value, including supported variables, object properties, and
destructuring. The appearance of the input tells you how an edit will work:

| Input                                     | Meaning                                                                                                        | What typing a number does                                          |
| ----------------------------------------- | -------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| An editable value                         | A literal or unique editable source was found                                                                  | Updates that source, preserving a supported expression around it   |
| An empty input with a numeric placeholder | An evaluated expression has no unique editable upstream value, or an omitted argument has an annotated default | Replaces the expression or appends an explicit argument if enabled |
| An empty input without a placeholder      | The argument is missing or has no evaluated value                                                              | Adds or replaces the argument if the input is enabled              |

For example, with `const spacing = 8`, changing X from `16` to `20` in
`box(spacing * 2, 8, 4)` updates `spacing` to `10`, leaving `spacing * 2`
intact. An inline coefficient is not treated as an upstream parameter:
`box(i * 8, 8, 4)` can instead show the evaluated X as a placeholder.
Typing `20` replaces `i * 8` with `20`, not the coefficient with another number.

Placeholder values are shown to at most three decimal places. Focusing an
input does not replace the expression; entering a value does, including when
it matches the placeholder. In a loop or function, the edit changes that
shared call site, not just the inspected runtime instance. Use Undo to restore
the original expression.

This differs from [dragging a position tool](../relations/#make-visual-adjustments),
which can preserve an expression by adding a numeric increment.

### Coordinate arrays

Position arguments such as `point([x, y, z])` and `pivot([x, y, z])` expose
separate X, Y, and Z fields. With a literal array, each field edits its own
component and can follow that component to a safe upstream numeric value.
For example, editing X in `pivot([reach, 0, 0])` can update `reach`.

The pivot's viewport handles use the same component mapping. If the argument
is an array expression whose individual components cannot be located in
source, the App does not guess where to write the three coordinates. Use a
literal array of editable components to make those controls available.
See [local coordinates](../../concepts/local-coordinates/) for the difference
between position arrays and scalar dimensions, offsets, and angles.

### Missing and spread arguments

An incomplete or failed call can still show a panel, even before a file has
produced any geometry. Omitted parameters with `default` show
their annotated defaults; other missing arguments remain blank. Only the next
argument that can be appended is editable, even when later parameters have
default placeholders. Editing never fills intermediate positions with
`undefined`.

At and after a spread argument such as `spacer(...args)`, the panel cannot
map individual parameter positions to source arguments. Those controls remain
disabled without default placeholders.

Focusing, leaving, or submitting an untouched default placeholder leaves the
call unchanged. Typing its value explicitly adds that argument, even if the
number matches the placeholder. Clearing an input is invalid and leaves the
source unchanged. Use Undo or edit the source to restore an omitted argument.

Use `Tab` to commit a value and move to the next input as it becomes available.
`Esc` cancels an active viewport drag, not the panel; leave the call in the
editor to close it.

Use runtime validation in the function for geometric requirements; input
constraints do not replace it.

## Custom primitives use the same annotations

For a `definePrimitive` result, put `@code3d.param` directly above the
`const` declaration. Its argument names, types, and optionality come from the
builder signature; panel defaults come from `@code3d.param`. Use ordinary calls to preview such a primitive;
`@code3d.arguments` does not create previews of primitive factory definitions.

See [custom primitives](../custom-primitives/) for the complete twisted-knob
example, including parameter tools, placement, and colors.

`@code3d.tool` marks a callable as a tool even when it has no numeric or topology-ID parameters. It does not make an arbitrary reference editable by itself; Core uses it for `aroundLine`, whose axis is handled by the App’s rotation reference picker. Use `@code3d.param` for ordinary editable model parameters.
