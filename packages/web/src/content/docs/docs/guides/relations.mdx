A relation describes how one part sits against another. It is attached to a
model value and resolved when the parts are composed.

<ModelExample id="first-model" />

## Connect two faces

In the example, `part.bottom.on(base.top)` makes the two planes coincide with
opposing normals. Their centers align by default, but centering is a preference:
other relations can slide the faces along their shared plane. Use `.flip()`
when their normals should point in the same direction.

An explicit `offset(x, y, z)` fixes the source anchor's position in the
**target anchor's frame**, including when all three values are zero. This lets
placement follow the part it is attached to. Repeated offsets add together.

The edge relation makes the reference lines collinear, while the face relation
places the second box below the first. Together they place the second box at
`[5, -15, 0]`; neither relation forces both anchor centers to match.

Points coincide with points or lie on reference lines and planes. Lines can
coincide or lie in a plane; two planes coincide with opposing normals. A
relation involving a complete frame fixes the complete pose. Edge and surface
anchors describe reference lines and planes, so their finite boundaries need
not match. Curved topology uses a sampled tangent or normal frame.

The solver chooses a nearby valid pose using centering and orientation
preferences. Conflicting relations report a failure; because solving is local
and nonlinear, a failure is not proof that every possible pose is invalid.

## Inspect the right scope

The related post on its own still displays in its local frame. Select the
`group` to see the post positioned against the base, or place the cursor in
the relation to inspect both participants. Selecting a named anchor or an
`edge`, `surface`, or `vertex` call keeps the other participant and downstream
composition peers visible while highlighting the selected anchor.

The callback parameter in `relate(part => ...)` is the new related model
value. Operations preserve the observable meaning of existing model values.

## Group or fuse

Use `group([base, post])` for separate parts. Use `union([base, post])`
when you want a single fused solid. Boolean operations also resolve operand
relations before evaluating geometry.

## Make visual adjustments

Enter an `offset` call in the source to use the position tool. Supported
parameter changes write back to the defining source values. A unique upstream
parameter takes priority when the tool can safely preview its uses. If it is
shared, other affected objects preview the change as well.

Without a safe upstream parameter, dragging preserves the offset expression
and adjusts it by an increment. For example, an X movement of `2` changes
`.offset((i - 2) * 8, 0, 0)` to `.offset((i - 2) * 8 + 2, 0, 0)`.
Another movement of `3` combines that increment into `+ 5`. Returning by `5`
removes it. The tool does not change the inner `8` or keep nesting offset calls.

Only the outermost offset is edited. When no offset is present, or its arguments
cannot be edited axis by axis, the tool appends one offset and reuses it on later
drags. A shared expression changes all of its runtime occurrences; it is not
an override for only the clicked part.

Release to commit the preview, or press `Esc` while dragging to cancel without
closing the panel. Use Undo after an edit has been committed. Numeric panel
input has a different meaning when an expression appears as a placeholder:
it [replaces the whole argument](../model-tools/#what-a-panel-can-edit).

To rotate the geometry itself or choose its pivot, see
[origins and rotation](../origins-and-rotation/).

See [code and geometry](../../concepts/code-and-geometry/) for the distinction
between a model value and its runtime context.
