A reusable model is an ordinary function. Pass dimensions in, return a model
value, and use `expose()` to name the elements that other parts should attach to.

## Name the interface

The function exposes `mountingFace`, `tipFace`, and `centerline`.
Callers receive these as typed elements: they can place the pin on the plate,
or attach a cap to its tip, without knowing how the pin was constructed.

Here `mountingFace` and `tipFace` name the body's `down` and `up`
directional bounds. Their type is `Bound`, and they describe finite extents.
Use `surface(id)` when the interface needs a particular topology face.

The exposed references are rebound into the returned model's frame. They
describe its public interface rather than leaking the placement of an internal
construction object.

## Expose geometry for further queries

Exposing a geometric model gives callers a topology reference to it:

```ts
import {box, group} from '@code3d/core';

const plate = box(32, 4, 24);
const assembly = group([plate]).expose({
  body: plate,
  mountingFace: plate.surface(1),
});

const boundary = assembly.mountingFace.edges();
const center = assembly.mountingFace.center;
```

`body` is a `Solid` reference; `mountingFace` remains a `Surface`. Face, edge,
and point models similarly become `Surface`, `Edge`, and `Vertex` references.
The references support queries and attachment relations, and retain named
members such as `assembly.body.up`. Model operations such as `fillet` or
`rotate` belong to the model values used to construct the assembly.

Chained queries preserve the assembly placement and the source geometry's IDs.
A relation through `self.mountingFace.center` places the entire `self` model.
If two child instances share a source, expose the intended child's reference
(`left.body` or `right.body`) to identify the placement.

Pure reference planes, axes, and calculated points remain anchors. They do
not gain a topological boundary merely by being given a name.

## Keep composition separate

The function defines the part's geometry and useful attachment points.
Its caller supplies the relation to another part. This keeps the same pin
useful in different assemblies.

## Publish the function

Move the function into its own TypeScript file and add `export`. Another file
can then import it by its normal relative path. The runtime does not require
a special model declaration wrapper.

Use the editor's completion list to explore the names on the returned model.

## Give callers visual controls

Add `@code3d.param` JSDoc annotations to the function to describe its editable
parameters. The App can then offer a panel at its call sites, while the
implementation stays an ordinary TypeScript function.
See [adding tools to model functions](../model-tools/) for a runnable example
and design-time previews with `@code3d.arguments`.

If the built-in modeling operations are not enough for a part, a
[custom primitive](../custom-primitives/) can use Replicad and still return
a model with the same relation, color, and tool capabilities.
