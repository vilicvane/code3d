# 二维草图求解器技术验证

日期：2026-09-06；关联 [#23](https://github.com/vilicvane/code3d/issues/23)。
用户批准先验证约束矩形、圆、拖动、尺寸和冲突，再讨论公开表示。
本文前半部分保留当时独立实验的结论与边界；后续产品接入见末节。

## 结论

现有 Ondsel 桥接能完成点线矩形和固定半径圆的局部求解；问题不是它完全不能算
二维几何，而是其未知量和约束接口面向刚体。把草图映射成刚体会引入多余的位置、
四元数、辅助杆和内部条件，仍没有直接表达可变圆半径、原生圆弧和草图自由度诊断。

PlaneGCS 的二维参数接口更贴合需求。本次在 Node 与主机 Chrome module Worker
分别通过 92 个检查，覆盖可变半径、相切、圆弧及约束诊断。
用户已于 2026-09-06 确认：装配继续用 OndselSolver，草图使用 PlaneGCS。
可以共用运行时加载、生命周期和诊断来源映射，不强行共用刚体问题格式。
没有将实验使用的第三方 JSON 模型或 `GcsWrapper` 选定为 Code3D 的公开 API。

## 输入与断言

实验坐标使用 XY 平面，与尚未确定的作者 tuple 格式无关。

- 矩形点依次为 `(0,0)`、`(1,0)`、`(1,0.75)`、`(0,0.75)`，锁定首点，
  四边分别加水平/垂直条件。从扰动初值求解宽 1、高 0.75。
- 欠约束拖动 40 步：第 `i` 步右上角目标为
  `(1 + i/80, 0.75 + sin(i/8)/8)`。每步以前一次求解结果作为点坐标初值，
  拖动只是低优先级目标。检查直角、目标位置与锁定首点；补上宽高后拖动不能改变尺寸。
- 冲突：同一底边同时要求宽 1 和 1.2，检查拒绝以及两条条件的来源 ID。
  PlaneGCS 另加一次重复水平条件，检查仍可解且报告冗余 ID。
- 尺度：原始 40 × 30 几何缩放 `1e-6`、`1`、`1e6`，并平移到
  `(8000 × scale, -9000 × scale)`；减去局部基点并以 `40 × scale`
  归一化后求解。这验证带归一化的输入流程，不是后端直接处理任意大数值的证明。
- Ondsel 固定半径圆：用两端距为 1 的刚性杆约束圆心和圆周点，后者限制在
  XY 平面，拖动目标在半径 1.2 上每次前进 10°，共 37 个位置。
  检查输出仍在半径 1 上、方向正确。没有把杆长当作未知半径。
- PlaneGCS 自由半径圆：圆心固定，圆周点和半径均为未知量；37 个方向位置，
  目标半径为 `0.8 + i/100`。检查圆周点和求解半径，临时拖动不减少持久自由度。
- PlaneGCS 三点定圆：固定点 `(4,2)`、`(1,5)`、`(-2,2)`；圆心初值
  `(0.8,1.9)`、半径 2.8。检查求得圆心 `(1,2)`、半径 3。
- PlaneGCS 两圆相切：圆心固定且相距 5，第一个半径固定为 2，第二个初值
  为 2.8，检查第二个求得半径 3。
- PlaneGCS 圆弧：固定圆心与起止角，将半径从 1 驱动到 2，使用 `arc_rules`
  保持端点与角度一致；分别检查 `0 → π/2`、`5.5 → 6.8`、`0 → 3π/2`。
  这是求解方程验证，不是有限圆弧裁剪、方向分支选择或区域生成验证。

几何断言容差为归一化坐标 `1e-6`。成功条件不仅是后端返回成功，还独立核对
位置、半径、圆弧端点以及固定上游。失败不自动当作数学上全局无解。

## 实测结果

| 检查组                                            | Ondsel 桥接 | PlaneGCS |
| ------------------------------------------------- | ----------: | -------: |
| 扰动矩形尺寸求解、40 步拖动、硬尺寸、冲突、3 尺度 |          46 |       46 |
| 固定半径圆周拖动                                  |          37 |        — |
| 冗余条件、平移后的锁定上游                        |           — |        2 |
| 自由半径拖动                                      |           — |       37 |
| 固定半径抵抗拖动、三点定圆、半径尺寸、两圆相切    |           — |        4 |
| 小弧、跨零角、大弧的半径编辑                      |           — |        3 |
| 每个运行环境的合计                                |       83/83 |    92/92 |

两套相同实验分别在 Node 和 Chrome Worker 通过；浏览器没有页面异常。
PlaneGCS 对锁定首点的欠约束矩形报告 2 个自由度，加宽高后为 0；
冲突尺寸返回失败及 `width` / `conflict`，重复水平约束返回可解及 `duplicate`。
这些不是正式产品的冲突最小集保证。

Chrome 中这批 40 步小矩形拖动的中位数约为 Ondsel 2.6 ms、PlaneGCS 0.1 ms。
只作探索观察：没有专门控制预热，两者输入表示、诊断和计时边界也不完全相同，
不能据此承诺固定倍数或大型草图性能。几何表示与诊断能力才是本次选型的依据。

## 实验结束时的接入问题

1. **正式后端边界。** 尚未确认采用第三方 npm 包还是固定 FreeCAD 源码自建小型
   WASM 桥接。实验没有完成可重建产物、异常/取消、长期内存与大型草图压力验收。
   发布包 metadata 与源码头的 LGPL 版本表述不一致，正式选型须核对实际源文件及分发要求，
   本文不据 metadata 作许可兼容性结论。
2. **当前数据与约束。** 用户已确认将几何当前数据与独立 `constraints` 区分，
   约束不持久化 ID；不得因数值原来写作变量或字面量而赋予不同求解语义。
   下一版显式尺寸和 X/Y 锁定都在创建时写成约束。既有表达式源码仍不得被擅自
   覆盖；具体几何/约束类型及求解结果重放、源码回写规则仍需落实。
3. **拖动与重放。** 拖动目标仅属于当前操作，不能留下隐形持久约束。最终接受的
   几何初值和显式约束需能从源码确定性重放；同一约束可有多个解，源码不能依赖
   GUI 内存中未保存的上一次解来选择分支。
4. **几何有效性。** 求解成功不等于 CAD 几何有效；零长度、非正半径、退化圆弧、
   分支翻转、相切与重叠、约束删除和裁剪后的身份更新尚需领域层和正式回归覆盖。
5. **作者身份与后端索引。** 编译时按依赖构建后端输入并映射回每层实体 ID，
   不采用第三方包装中的插入顺序作为源码 ID，不因后端构建顺序重排作者数组。

一次性探针和下载产物在结论记录后移出活动临时目录，不进入正常运行路径。
上述实验本身没有改变 App、Node 模型运行时和草图公开格式。

## 2026-09-06 点线约束接入

用户确认几何当前数据与独立约束后，正式采用固定版本
`@salusoft89/planegcs@1.2.0` 的未修改 JS/WASM 产物，直接使用 `GcsSystem`，
不采用第三方 JSON 模型或 `GcsWrapper`。来源与许可原文位置见
[core 第三方说明](../packages/core/THIRD_PARTY.md)；未声称已完成自行重建产物。

- App 的项目包运行时和 Node 入口加载同一求解器；装配仍使用 Ondsel。
- 作者格式为 `sketch(entries, {constraints})` / `base.derive(entries, {constraints})`，
  约束不持久化 ID。点线支持 fixed、x/y、horizontal/vertical、coincident、length、angle。
- 每次从当前几何和约束创建独立原生系统，归一化后求解；拖动仅是负 tag 软目标。
  `Success` / `Converged` 都须通过独立硬约束残差验证；冲突索引映射回源码 tuple。
- 拖动结果批量回写当前层可编辑坐标，保留表达式与上游，提交后重新编译重放。
  绘制的显式数字和最终 X/Y 方向锁定与几何一次写入、一次撤销；自动吸附不加约束。
- 正式测试覆盖点线、派生锁定、尺度、确定性重放、冲突/冗余和连续 2,100 轮
  成功及失败释放，检查 WASM heap 与存活绑定句柄不增长。

圆/圆弧的作者格式、剪刀分裂和闭合区域仍属于后续功能；上述探索通过不表示这些
几何已经接入产品。大型草图性能也没有据小规模实验作保证。

## 连续旋转、源码重放与弱位置保持的追加调查

用户报告拖动松手跳变及接近 180° 时线段翻转。前者要求预览验证与实际源码
提交相同的求解输入（包括写回精度），后者需要每帧从上一帧解连续求解，不能
始终从手势起始几何重新求解。对长度 40、另一端临时固定的线段，以 2.5° 步长
旋转一周：原始种子路径最大相邻位移约 79.95，上一帧种子路径约 1.75。
这是独立实验，不是完成 GUI 修复的验收记录。

尝试添加每个点的负 tag 弱坐标保持后，固定发布包出现两个可独立复现的问题：

- 单个 horizontal 约束会被原生 Equal 参数消元，余下仅软目标的子系统被交给
  DogLeg 普通方程求解。合并后的坐标具有不同保持目标，软目标无法全部归零，
  因而可能返回 Failed；BFGS 能到达平均位置并返回 Converged。
- 冗余诊断的 Jacobian 排除了负 tag，但随后用于判定冲突/冗余的临时求解
  `clistTmp` 只检查 `isDriving()` 和是否被跳过，没有排除负 tag。软保持因此
  混入硬方程一致性检查，两个相同 horizontal 会被误报为冲突。

源码证据为固定 npm gitHead 的
[GCS.cpp](https://github.com/Salusoft89/planegcs/blob/ee9b156da9827a91a56a888a53520f63d5cffaa6/planegcs/GCS.cpp)
中的 `initSolution`、`solve`、`makeReducedJacobian` 和
`identifyConflictingRedundantConstraints`。独立测试比较了 Equal/Difference
表示及 BFGS/LM/DogLeg；换算法或把水平条件改写为 Difference 都不能一并解决
冗余误报。因此不接受通过忽略 Failed、冲突标签或放宽硬约束残差掩盖问题。

用户选择先调整锚点策略，不扩大到原生 WASM 修订。全体点弱保持已移除；
没有修改上游仓库或发布新的第三方产物。手势没有上游锁定、fixed 或完整 X/Y
定位点时，固定第一个非拖动点；不加入持久约束，正常求解不采用隐式锚点。
无约束移动由同一数值入口直接计算，不需要原生内核或等待进行中的模型编译。

正式回归覆盖两个端点各转两圈、已有固定点不增加锚点、持久 DOF 不受影响；
编译回归对可回写数值点检查整圈预览及 177.5°、182.5°、360° 的源码重放。
源码保存求解后的绝对坐标，而不是向未满足约束的旧数据叠加位移；包含舍入后的
正向预览。零运动不修改作者数据。这些检查通过，不等于整个稳定性问题解决。

仍保留两项已知边界：表达式初值不回写时，正向预览/重新编译会移动手势中
固定的显示锚点（已观察从约 `[24.155, 20.832]` 回到 `[22, 19]`）；重复水平
约束加鼠标软目标仍可能触发上述冗余诊断误报。它们不是数值断言放宽或隐藏
GUI 状态所能掩盖的已完成能力，后续决定和验收继续在 #23 跟踪。
