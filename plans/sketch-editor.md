# 草图编辑器：工具调研与实施顺序

关联需求：[#23](https://github.com/vilicvane/code3d/issues/23)。调研日期：2026-09-05。
本文按用户要求记录常见 CAD 的能力、Code3D 的优先级建议和待讨论问题；
不是全部已确认的 API，也不另行维护任务状态。具体进展与验收记录在 issue。

## 已确认的边界

- 草图以可视化编辑为主，源码仍是唯一持久状态；使用 `sketch([...])` 和
  `[kind, ID, data]` tuple，不以链式绘图 API 为主线。
  工具新增实体、插入约束及 Trim 拷贝统一按源码所在行和容器层级生成缩进，
  保留外层空白、原有换行格式及作者表达式/注释。每层使用与编辑器一致的两个空格；
  不在绘图过程中提前调用 Prettier，重新获得代码编辑器焦点时仍按统一流程格式化。
- 画布铺满右侧 viewport，工具浮在画布上。viewport 状态和错误卡片仅显示当前草图
  及上游定义求值的错误，不显示无关草图、3D 或下游错误；编辑器诊断不受过滤影响。
  仅当当前草图本次未能重新求值时保留原选中范围的最后成功快照，并明确只读、
  不可误作已更新结果；已成功求值的草图不会因下游/无关错误临时只读或重置绘图/Trim 工具。
- 工具栏固定右上，纯图标、hover 显示名称，分开编辑/绘制/视图组；用当前工具强调与
  轻量开关状态区分操作模式和视图设置。窄 viewport 保留完整分组并避开左上状态。
  键盘使用单 Tab 停靠点和方向键导航，不挤占绘图数字输入的快捷键。
- 点是 `['point', 1, [x, y]]`，线是 `['line', 3, [1, 2]]`；端点数字引用
  本层点，不是坐标。实体 ID 在每层独立，不持久化 `nextId`，不重排存活 ID。
- 点数据也可为本层 ID 或具名上游引用，如 `['point', 11, 1]`：
  是同一几何点的别名，共用最终目标的求解变量，保留引用方 ID。允许链、拒绝循环/缺失。
  拖动遵循最终目标的编辑权限，上游只读；明确吸附已有点时松手写入别名，取消不写。
  本次引用合并会使直线退化时，在求解前删除该本层直线及对应约束，保留两点 ID。
  吸附时预览完整事务，移开恢复原拓扑；松手一次提交/撤销，保留其他曲线的拖动随动和连接。
  不能用别名覆盖表达式坐标，也不能借合并重新定义 fixed；失败整笔拒绝。
  相近坐标不自动去重。数值尾差按局部图元尺度简化后独立核对硬约束/圆弧结构，
  优先准确输入及拖动值；源码写回无损，预览与重编译使用同一组数据。
  圆弧径向拖动直接缩放已有方向向量，不经角度与三角函数往返重建轴向坐标，
  避免把计算产生的尾差当作准确初值保留；不据此全局舍入已有作者数据。
- 圆是 `['circle', id, [centerPoint, radius]]`：圆心引用普通本层/具名上游点，
  半径是当前几何数据。约束统一为 `['kind', target, value?]`；多个点时 target 为数组。
  显式输入半径写入独立 `['radius', circleId, value]` 约束；
  不输入则自由。拖圆心移动、拖圆周调整半径；不生成圆周点或折线近似。
  点坐标和半径共用数值参数、AST 可编辑性、手势锁定与舍入后正向重放；表达式不覆盖。
  原生圆与半径约束使用 PlaneGCS。已锁定标量方程先直接验证，避免常量方程在原生
  冗余诊断中误报冲突；真实矛盾仍失败。半径标记连接实际圆心与圆周。
- 圆弧采用 `['arc', id, [centerPoint, radius, startPoint, endPoint, 'cw' | 'ccw']]`。
  半径与点坐标都是当前数据，原生 ArcRules 保持端点位于该圆上；不持久化角度初值。
  初值不一致时，按圆心/半径与端点方向同时投影，共享端点取平均建议而非顺序覆盖；
  已有显式半径约束时使用其尺寸作为初始半径，否则使用普通半径数据，避免先投影到
  矛盾尺寸再回缩时导致无锚定弧漂移。手势锁定半径不覆盖，冲突仍验证。
  已锁定、上游、fixed 和显式 X/Y 轴不改。之后统一求解结构和显式约束，半径仍可变。
  投影只建立求解起点，不增加持久约束、软目标或自由度。
  `radius` 约束可指向本层圆或圆弧。方向显式决定大/小弧与跨零角区间；零半径和起终点
  重合拒绝，整圆使用 circle。Arc 工具按圆心、起点/半径、终点三步创建，R 反转方向，
  新绘制默认顺时针 CW，取消或完成后恢复 CW，不改变已有显式方向。
  中心/端点复用实际点引用，显式 X/Y/Radius 与几何同事务提交和撤销。
  求解、端点/弧边半径拖动、表达式锁、舍入后源码重放共用既有路径。圆/圆弧显示、拾取、边界和
  半径标记共用解析曲线计算；删除按有限几何清理新孤点，不把圆弧缺口当作连接。
- 扫角使用独立 `['sweep', arcId, degrees]` 约束，严格 `0 < degrees < 360`，
  只引用本层圆弧；方向仍由 arc 的 cw/ccw 决定。Arc 最后一步可输 Sweep，
  空白时自由跟随鼠标，R 反转方向但保持已输入幅度。显式扫角与几何同事务提交和撤销。
  求解器的临时角参数按有向弧展开，独立验证实际扫角，跨半圈和零角不改变大小弧分支。
  扫角标记关联实际圆心、起终点与弧。由已知点确定的尺寸直接验证，不作为冗余方程
  交给原生求解；已固定坐标不再重复施加不可达鼠标目标，真实约束冲突仍拒绝。
- 派生层锁定上游。通过具名上游的 `base.point(id)` 建立跨层引用，不使用祖先
  深度数字，也不为匿名上游设计特殊引用语法。缺失引用报告错误，不默默换目标。
- 普通 JavaScript/TypeScript 表达式仍然有效。不能反向编辑的表达式明确只读，
  不把 `width / 2` 偷换成一次求值的数字，也不在 GUI 中保留隐藏模型状态。
- `sketch(entries, {constraints})` 明确区分几何当前数据与独立约束；不把 `length` 等约束和
  `point` / `line` 几何实体混放在同一类条目里。约束不持久化 ID，源码范围与本次
  求解的临时标识承担编辑和诊断定位。单目标约束直接使用引用，例如
  `['fixed', 1]`、`['horizontal', 3]`；多个参数仍可用 tuple data。
- 2026-09-06 用户确认并接入点线约束：显式输入的尺寸以及 X/Y 方向锁定都在成功创建时
  成为持久约束。X 生成水平、Y 生成垂直，提交前解除锁定则不生成方向约束；
  切换轴只保留最终方向。取消草稿不留下几何或约束，两者以同一源码事务提交和撤销。
  这取代原点线版本的“一次性数值/方向”设计。普通自动吸附不因此
  自动升级成约束。
- 直线按已有点/交点分段选择和删除；只在实际删除时持久化分割。剩一段保留旧线 ID，
  剩两段退役旧 ID、分配两个新 ID。删除产生的本层孤点及相关约束一起移除，
  共享点（含 T 形连接）、上游点、无关独立点和其他线保留。原整线长度约束移除，
  仍适用的方向约束及其表达式跟随剩余线；几何与约束同事务提交和撤销。
  同一本层区间的重叠直线（含反向）整组高亮、提示数量、一次修剪并一次撤销。
  每条原线独立保留/分配 ID 和映射约束，新交点共享，整批结束后清理孤点；
  任一目标不能安全改写时整批拒绝。不是全局去重，不影响近邻平行线、相交线或只读上游。
- Trim 使用剪刀图标，悬停预览、直接点击修剪、Esc 退出，不依赖选择。
  直线分段接受圆和有限圆弧作为边界（包括只读上游）；切割曲线本身保持不变。
  求交共用解析几何与模型精度，不依赖屏幕折线；相切、重叠边界和圆弧缺口分别处理。
  Select + Delete/Backspace 保留并复用同一事务。持久约束默认显示图标与数值，
  可整体隐藏，悬停/聚焦高亮真实关联几何；上游标记区分显示，中点画中心到两端的引导线。
- 圆与圆弧自身也使用同一解析区间修剪。圆按循环区间分段，不人为增加零角接缝，
  零或一个唯一分界点时整圆删除。剪去一段后的圆转为 CW 弧并保留 ID；有限弧遵循
  一段保留、两段退役旧 ID，方向不变。圆心引用、半径表达式及半径约束跟随存活弧，
  原整弧 sweep 如整线 length 一样删除。重合圆/弧按相同区间整批处理，共享交点，
  一次回写/撤销；上游不改，不暗加点在曲线上的关联约束。

当前版本已有选择、连续线、两种矩形、圆和圆弧创建、字面量点/半径拖动、局部删除、上游锁定、缩放/平移、
源码事务与撤销。没有独立 Point 创建入口；点保留为端点与引用实体。每段提交后
复用终点 ID 继续绘制，Esc 结束当前连线、保留完成段，再按一次退出工具。
绘制共用数字输入（起点 X/Y 或线段长度/角度）与点、原点、网格、方向
吸附，并支持 X/Y 切换或解除当前线段的水平/垂直方向锁定。显式数值/方向生成
约束，拖动经过求解后原子回写全部变化的可编辑点。交互契约见
[TOOLING.md](../TOOLING.md#草图编辑)。直线、圆与圆弧已有分段删除，并接入闭合
非相交轮廓的区域预览、真实 B-Rep 面、拉伸及 loft。当前边界与后续优先级如下。

## 已确认的区域与建模 API

- `s.face()` 恰好返回一个有效面（允许孔洞），零个或多个报错；`s.faces()` 返回普通
  只读数组，与 `edges()/surfaces()/vertices()` 一致，不挂几何方法。未来增加
  `face(id)/faces(ids)` 时保留无参语义；本片不定义持久区域 ID，更不使用数组下标替代。
- `face.extrude(distance)` 与 `extrude(face, distance)` 共用单面运算。批量写
  `faces.map(face => face.extrude(distance))`，不加数组重载。
  `stock.cut(tools)` 等价于已有 `cut(stock, tools)`；布尔工具和 loft 截面数组表示
  单次运算输入，与批量映射区分。
- 区域包含当前及上游全部边界，独立区域分开，嵌套轮廓按实体/孔/岛交替；独立点忽略。
  开放、自交、重叠、分叉及轮廓相切诊断；不自动补线、丢弃边、改实体 ID 或修改上游。
  任意平面 arrangement 自动取面尚未实现，当前需要先修剪为互不相交的闭合轮廓。
- 草图 `[x,y]` 到模型 `[x,0,-y]`，不自动居中。正拉伸沿平面法向，负值反向；
  零和非有限距离拒绝。旋转/原点/关系操作沿用模型语义。
- loft 支持无孔及每截面一个孔（含 spine），保留真实孔壁；孔数不符或多个孔没有
  明确对应时诊断，不按遍历顺序匹配，不静默填平孔洞。多孔对应 API 待实际需求再定。
- 区域预览不拦截拾取，不生成源码实体；开放草图仍可正常编辑，只在调用建模出口时报错。
  验收示例：`examples/sketch-modeling.ts`，修改草图后查看 plate、tools 和 duct。

## 建议优先级与依赖

P0 是第一套可精确绘制、编辑并用于建模的闭环；表中按依赖拆成可验收的小步。
P1/P2 是其后的扩展，不代表现在就承诺全部实现，也不以工期估算代替技术验证。

| 优先级 / 顺序 | 能力                             | 完成条件与前置依赖                                                                                           |
| ------------- | -------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| P0 · A        | 统一绘制会话、数字输入、吸附基础 | 一套预览/提交/取消与焦点规则；线长/角度、点 XY；网格、端点、原点、水平/垂直提示；一次操作一次撤销            |
| P0 · B        | 几何与约束数据基础               | 原生圆/圆弧，不以折线代替；可源码表示的基本重合、水平/垂直、固定及尺寸约束；验证求解器边界后再定公开格式     |
| P0 · C        | 常用创建工具                     | 连续线/闭合线、对角点矩形、中心矩形、圆心圆、基础圆弧；绘制中输入长宽/半径；矩形后续拖动仍保持直角           |
| P0 · D        | 剪刀、分割和构造几何             | 线/圆/圆弧交点与区间；悬停预览、点击修剪；相交、相切、重叠及退化情况可解释；ID 和受影响约束一起处理          |
| P0 · E        | 区域与建模出口                   | 闭合环、孔洞、方向、区域预览、线框/面转换与拉伸接入；明确点线面引用规则；不能只输出屏幕填色                  |
| P1            | 尺寸和约束深化                   | 后置尺寸编辑、参考尺寸、平行/垂直、等长/等半径、相切、同心、中点；欠约束/冲突定位与可撤销删除，不暗中丢约束  |

| P2            | 更广工作空间                     | 任意附着平面、跨平面参考、3D 草图、文字等按实际使用反馈再选；不阻塞首个 2D 闭环                              |

剪刀在第一套闭环内，不等所有高阶工具完成后再补。实现顺序先有圆弧再裁剪圆，
因为裁掉圆的一部分会得到圆弧。区域提取不应改变草图的原始实体；画线交叉也不
自动把作者的一条线改成两个 ID。

对角点矩形已接入现有绘制契约：首角 X/Y、对角宽高、四象限预览、真实角点吸附、
一次源码事务/撤销。输出四点四线与四条水平/垂直约束；宽高只各约束一条相邻边，
避免重复尺寸。没有新增矩形实体或隐式中心。角点拖动采用软参考，参考点必要时可以移动，
不因临时硬锚点阻止原本可行的轴向移动。

用户确认的中心矩形保留一个普通中心点，通过通用
`['midpoint', [center, oppositeA, oppositeB]]` 与一对对角点建立关系；
结合四条水平/垂直约束即可关联全部四角，不需要第二组中心关系或对角线实体。
与对角点矩形共享绘制实现，Width/Height 都指完整边长，中心和所选角点可复用
真实吸附引用。中心先于新角点分配 ID，派生层可使用 `base.point(id)` 引用它。
拖中心由规则生成整体平移的软目标，真实约束优先；删除引用点时同步清理中点约束。

拖动框架只按序调度规则，传入完整上下文，不提前分类点或拆分连通部分。
规则自行识别角色和关系，首批覆盖中心平移、端点软参考及唯一无约束交点的分支策略。
端点优先参考关联中心，否则沿实体/约束图选最远点；坐标重合或几何相交不建立身份关系。
点在曲线规则按手势起始的显示几何与修剪共用模型容差，统一识别直线、圆和圆弧上的已有点。
保留曲线 ID 与类型，点可沿曲线滑动；端点、圆心和半径变化时在线点随动，并有软姿态参考。
圆心优先平移附着点，半径变化优先保留它们的极角；极坐标初值使半圈拖动可以直接到达另一支。
临时直线/径向方程与有限端点边界不写入 constraints；圆弧按 CW/CCW 实际弧段约束，不扩大为整圆。
AST 锁、显式约束和只读上游优先，源码正向重放独立复核关系。途中过线不粘连，不生成交点、不合并身份。
中心规则允许连接外围线段，不再因存在外部几何或附加限制退出。
通用执行器依次求解规则返回的目标组：鼠标最近可达结果 → 局部平移 → 外围少动。
平移取手势起始坐标加实际可达圆心的位移，共心圆/圆弧半径优先保持原值；
外围点通过约束响应。所有层保留作者方程、AST 锁、上游只读和手势在线关系。
每层先软求解，后层临时保留前层已取得的目标参数，不将原参考位置预设为硬锚，
也不是一组失败就换下一候选。首版保留前层选中的解，不保留所有等价最优解空间。
阶段锁只存在当前帧；下一帧重新建立，不能使后续拖动或反向归位失去自由度。
手势保留开始时的参考几何，每帧仍以上一帧解为数值起点；不持久化策略、临时约束或改变 DOF。
交互线在普通、选中、约束关联和修剪状态统一为 2px。

## 工具菜单与选中后的约束

右上工具按选择、绘制（线、矩形变体、圆、圆弧）、修改（Trim）、视图排列。
矩形/中心矩形共享记忆最近使用项的分裂按钮，菜单及图标工具保留键盘导航与可访问名称；
领域图标使用 Lucide 同样的 SVG/stroke 契约，绘制图标的端点与中心点对应实际生成的点，
统一大小；直线斜置，矩形无圆角。长度使用尺子，角度使用半圆刻度量角器，水平/垂直
使用主方向实线、参考方向疏虚线的无端点十字，保持颜色、透明度和线宽一致。分隔线贯穿工具栏内侧，分隔线两侧与外围
统一留白，不改变按钮尺寸。右键拖动平移且不取消草稿，中键/空格左键仍可用。
不再显示左下常驻操作说明；错误、只读原因、绘制尺寸和悬停说明保留。

Shift 点击增减选择。点可追加 fixed、X/Y coordinate，两个点可 coincident；点加本层线
或三个点（先选中心，再选两个端点）可 midpoint；
本层线可批量 horizontal/vertical/length/angle，圆和圆弧可 radius，圆弧可 sweep。
尺寸共用绘制数字输入，默认当前显示值，取消不写，完成一次源码事务/撤销；已存在
同类型约束不重复追加；全部已有时按钮保持启用并高亮，点击取消；部分已有时显示混合态并补齐。
取消保留当前可写几何，不恢复旧初值，表达式原文不改。约束指向整个源码图元，
不是临时分段；多选删除仍作用于所选区间，存活区间按图元合并，失联孤点与约束一起清理。
图中约束标记可单击或用 Enter/Space 激活，切回 Select 并选中相关点或整个源码曲线。
本层数值字面量尺寸自动打开输入框，选中完整原值；确认只替换该约束的值节点，
不删后重加，不改变约束顺序、其他值或注释，一次源码撤销恢复。
取消、切换选择、离开草图或源码更新关闭未提交输入；上游和表达式值只选中，不提供数值改写。
工具栏已施加的按钮仍表示移除约束，不与标记的点击编辑混淆。
坐标约束明确标为 X coordinate/Y coordinate，使用 X=/Y= 图标；方向、长度、半径及角度
使用各自的工程示意，工具栏与画布标记共享 Lucide 风格 SVG，不用移动箭头代表坐标约束。
新增线间关系和框选仍属于后续能力，本轮不伪装成已有功能。

## 数字输入与吸附：先建立可复用的交互能力

以下是建议交互，不照搬任何一家软件的全部快捷键：

- 绘制会话拥有当前工具、阶段、草稿、吸附候选和尺寸字段。预览不写源码；完成一条
  线、一个矩形或一次裁剪时提交完整事务。连续线按每段撤销，矩形按整个矩形撤销。
- 在线工具中先定起点，再输入长度和角度；矩形输入宽高；圆输入半径，提供明确的
  半径/直径切换。字段显示几何意义，而不是无标签的输入框。
- 未指定的量继续跟随鼠标；用户输入的量不被下一次 `pointermove` 覆盖。数字键
  激活当前字段，Tab / Shift+Tab 切换本次绘制的字段，Enter 完成当前步骤，
  Escape 取消当前草稿，再次 Escape 退出工具。工具快捷键只在草图作用域生效。
- 当前线段支持 X 水平、Y 垂直、同键解除；在画布或数字字段中均可触发。
  轴锁允许正负两个方向，保留已输入长度，与角度字段互斥；最后一次输入生效。
  Snap/Alt 只影响吸附，不解除锁轴。提交时将最终有效的轴锁写成持久约束，
  然后复位当前绘制状态；取消不写入约束。已经提交的约束不被下一段的按键开关改变。
- `-`、`1.` 等输入中的文本不触发重算覆盖。非法完成值留在字段中解释，不能提交
  NaN、零长度线或负半径。IME、粘贴、退格、焦点离开、指针取消都有独立测试。
- 数字输入框与画布属于同一绘制会话，不能沿用“画布 blur 就取消一切”。正常
  键盘导航仍可离开工具；仅活动绘制会话的字段循环，不全局截获 Tab。
- 输入框里的撤销先保留文本编辑语义，已完成几何的撤销复用现有源码历史；返回
  Monaco 焦点时沿用现有格式化与光标映射，不在拖动中格式化整份源码。
- 吸附使用屏幕像素阈值、稳定的优先级和可视提示，放大缩小时手感一致。先端点、
  原点和网格；随后加入中点、圆心、交点、切线。明确提示引用的是本层还是上游。
  当前网格按 1/2/5 细分，保持约 8–20 像素小格并每五格加深；显示与吸附共用间距。
- “临时吸附坐标”“一次性精确创建”“持久几何约束”是不同语义。只有可以写入
  源码并再次求解的关系才显示成约束；不把坐标取整伪装成水平/垂直约束。

表达式输入需要和源码参数编辑共享解析、补全、验证基础。可以先完成数值字面量
交互，但如果后续允许输入 `width / 2`，应保留表达式本身并由正常编译求值，
不能在 UI `eval` 后只存最终数字。该表达式如何作为驱动尺寸落入 tuple，见下节。

## 持久表示与稳定引用：实现前需要讨论的点

这里列出的倾向不是已确认 API；不在本文固定新的 tuple 位置参数。

1. **圆/圆弧已落实。** 使用上节确认的中心/半径/端点/方向 tuple 和原生求解，解析区间覆盖
   大弧、小弧与跨零角，完整圆使用 circle；不引入有损折线表示。
2. **矩形。** 倾向将矩形作为创建工具，产出普通点线和显式关系，不额外引入
   隐式“矩形编辑状态”。若只写四点坐标，拖一个点即可变四边形，不算完整矩形能力。
3. **坐标、尺寸与约束谁驱动（点线已落实）。** 几何当前数据与独立约束分开。
   点坐标无论来自变量还是字面量，运行时语义相同；固定位置和驱动尺寸由显式约束
   决定。编辑器不覆盖表达式坐标；拖拽时从 AST 逐轴判断，把表达式轴锁在本次
   源码的求值（不是可能已被普通求解移动的显示位置）。`[width, 0]` 锁 X、可拖 Y。
   锁值改变几何时先满足这些锁与已有约束，再准备拖动规则的参考几何；
   初始未满足约束的数据在首次施加这些锁时可以调整。只回写可编辑轴的绝对解，
   对舍入后的实际源码数据做正向预览，保证与重编译使用相同输入，不追加表达式偏移。
4. **一条曲线裁成两条（直线已落实）。** 用户确认一对一保留旧 ID，一分为二退役
   旧 ID、给两段新 ID，不任意让旧引用指向其中一段。直线按已有点、交点和重叠端点
   删除局部并清理本次失去连接的孤点，保留其他实体；长度约束移除，方向约束映射到剩余线且保留表达式。
   重叠直线以点击区间为一批处理，区间外部分仍保留各自身份，不合并原线 ID。
   本地关系同事务更新，不能安全定位的引用明确拒绝编辑。曲线修剪仍需接入解析区间；
   既定的无 `nextId` 策略保持不变，不以裁剪为由恢复它。
5. **派生时修剪上游。** 上游可作吸附/裁剪边界，但不能直接修改上游数组。是否提供
   显式派生裁剪/替换操作，或要求先创建本层几何，应单独决定；视觉上仍需区分所有权。
6. **面的身份。** 闭环顺序、填充区域下标和内核遍历顺序都不适合作为稳定公开 ID。
   区域分裂、合并和孔洞变化要有明确的引用决议；具体句柄/API 在建模出口阶段确认。

## Lucide 接入

App 使用原生 JavaScript 包 `lucide`，草图的选择、线、修剪、约束、
适配视图、吸附及绘制确认/取消按钮。保留明确按钮名称；SVG 仅作装饰，16px、`currentColor`、不可独立

## 第一套闭环的验收场景

- 空草图连续画线，用长度/角度输入，回到起点闭合；快速 Tab 不跳出页面，
  Escape 不留下半条线，源码撤销后 ID 和选择跟随恢复。
- 输入 40 × 30 创建矩形、创建半径 5 的圆；缩放后仍可精确吸附。尺寸可再次
  编辑，拖动后矩形保持直角，显示的参考尺寸与驱动尺寸不混淆。
- 剪掉交点之间的线段或圆弧，预览与实际结果一致；覆盖相切、重复交点、重叠线、
  闭合圆、极短段和大/小尺度。一次撤销同时恢复实体及相关约束。
- 以具名上游派生局部几何，修改上游坐标后引用仍正确；删除上游被引用点得到
  可定位错误，不自动引用另一个点。重编译不重排未变实体。
- 将带孔闭环转换为面并拉伸；开放线框、构造线、自交和多个区域有明确结果或诊断。
- 手写表达式、注释和无关 tuple 在工具更新后保留；保存、重载和 Node 执行所得
  几何一致。浏览器测试覆盖输入焦点、工具切换、派生编辑和源码来回编辑。
