# 草图编辑器：工具调研与实施顺序

关联需求：[#23](https://github.com/vilicvane/code3d/issues/23)。调研日期：2026-09-05。
本文按用户要求记录常见 CAD 的能力、Code3D 的优先级建议和待讨论问题；
不是全部已确认的 API，也不另行维护任务状态。具体进展与验收记录在 issue。

## 已确认的边界

- 草图以可视化编辑为主，源码仍是唯一持久状态；使用 `sketch([...])` 和
  `[kind, ID, data]` tuple，不以链式绘图 API 为主线。
- 点是 `['point', 1, [x, y]]`，线是 `['line', 3, [1, 2]]`；端点数字引用
  本层点，不是坐标。实体 ID 在每层独立，不持久化 `nextId`，不重排存活 ID。
- 派生层锁定上游。通过具名上游的 `base.point(id)` 建立跨层引用，不使用祖先
  深度数字，也不为匿名上游设计特殊引用语法。缺失引用报告错误，不默默换目标。
- 普通 JavaScript/TypeScript 表达式仍然有效。不能反向编辑的表达式明确只读，
  不把 `width / 2` 偷换成一次求值的数字，也不在 GUI 中保留隐藏模型状态。
- `sketch(entries, {constraints})` 明确区分几何当前数据与独立约束；不把 `length` 等约束和
  `point` / `line` 几何实体混放在同一类条目里。约束不持久化 ID，源码范围与本次
  求解的临时标识承担编辑和诊断定位。单目标约束直接使用引用，例如
  `['fixed', 1]`、`['horizontal', 3]`；多个参数仍可用 tuple data。
- 2026-09-06 用户确认并接入点线约束：显式输入的尺寸以及 X/Y 方向锁定都在成功创建时
  成为持久约束。X 生成水平、Y 生成垂直，提交前解除锁定则不生成方向约束；
  切换轴只保留最终方向。取消草稿不留下几何或约束，两者以同一源码事务提交和撤销。
  这取代原点线版本的“一次性数值/方向”设计。普通自动吸附不因此
  自动升级成约束。

当前点线版本已有选择、连续线创建、字面量点拖动、局部删除、上游锁定、缩放/平移、
源码事务与撤销。没有独立 Point 创建入口；点保留为端点与引用实体。每段提交后
复用终点 ID 继续绘制，Esc 结束当前连线、保留完成段，再按一次退出工具。
绘制共用数字输入（起点 X/Y 或线段长度/角度）与点、原点、网格、方向
吸附，并支持 X/Y 切换或解除当前线段的水平/垂直方向锁定。显式数值/方向生成
约束，拖动经过求解后原子回写全部变化的可编辑点。交互契约见
[TOOLING.md](../TOOLING.md#草图编辑)。它尚无圆/圆弧、裁剪或
区域/B-Rep 生成。下面规划后续闭环，不把当前 SVG 绘图视为完整草图功能。

## 建议优先级与依赖

P0 是第一套可精确绘制、编辑并用于建模的闭环；表中按依赖拆成可验收的小步。
P1/P2 是其后的扩展，不代表现在就承诺全部实现，也不以工期估算代替技术验证。

剪刀在第一套闭环内，不等所有高阶工具完成后再补。实现顺序先有圆弧再裁剪圆，
因为裁掉圆的一部分会得到圆弧。区域提取不应改变草图的原始实体；画线交叉也不
自动把作者的一条线改成两个 ID。

## 数字输入与吸附：先建立可复用的交互能力

以下是建议交互，不照搬任何一家软件的全部快捷键：

- 绘制会话拥有当前工具、阶段、草稿、吸附候选和尺寸字段。预览不写源码；完成一条
  线、一个矩形或一次裁剪时提交完整事务。连续线按每段撤销，矩形按整个矩形撤销。
- 在线工具中先定起点，再输入长度和角度；矩形输入宽高；圆输入半径，提供明确的
  半径/直径切换。字段显示几何意义，而不是无标签的输入框。
- 未指定的量继续跟随鼠标；用户输入的量不被下一次 `pointermove` 覆盖。数字键
  激活当前字段，Tab / Shift+Tab 切换本次绘制的字段，Enter 完成当前步骤，
  Escape 取消当前草稿，再次 Escape 退出工具。工具快捷键只在草图作用域生效。
- 当前线段支持 X 水平、Y 垂直、同键解除；在画布或数字字段中均可触发。
  轴锁允许正负两个方向，保留已输入长度，与角度字段互斥；最后一次输入生效。
  Snap/Alt 只影响吸附，不解除锁轴。提交时将最终有效的轴锁写成持久约束，
  然后复位当前绘制状态；取消不写入约束。已经提交的约束不被下一段的按键开关改变。
- `-`、`1.` 等输入中的文本不触发重算覆盖。非法完成值留在字段中解释，不能提交
  NaN、零长度线或负半径。IME、粘贴、退格、焦点离开、指针取消都有独立测试。
- 数字输入框与画布属于同一绘制会话，不能沿用“画布 blur 就取消一切”。正常
  键盘导航仍可离开工具；仅活动绘制会话的字段循环，不全局截获 Tab。
- 输入框里的撤销先保留文本编辑语义，已完成几何的撤销复用现有源码历史；返回
  Monaco 焦点时沿用现有格式化与光标映射，不在拖动中格式化整份源码。
- 吸附使用屏幕像素阈值、稳定的优先级和可视提示，放大缩小时手感一致。先端点、
  原点和网格；随后加入中点、圆心、交点、切线。明确提示引用的是本层还是上游。
  当前网格按 1/2/5 细分，保持约 8–20 像素小格并每五格加深；显示与吸附共用间距。
- “临时吸附坐标”“一次性精确创建”“持久几何约束”是不同语义。只有可以写入
  源码并再次求解的关系才显示成约束；不把坐标取整伪装成水平/垂直约束。

表达式输入需要和源码参数编辑共享解析、补全、验证基础。可以先完成数值字面量
交互，但如果后续允许输入 `width / 2`，应保留表达式本身并由正常编译求值，
不能在 UI `eval` 后只存最终数字。该表达式如何作为驱动尺寸落入 tuple，见下节。

## 持久表示与稳定引用：实现前需要讨论的点

这里列出的倾向不是已确认 API；不在本文固定新的 tuple 位置参数。

1. **圆与圆弧。** 倾向用原生实体、引用中心/端点，显式表达圆弧方向与扫角；
   要同时解释大弧、小弧、跨零角和完整圆。不能为迁就当前 SVG 结构引入有损表示。
2. **矩形。** 倾向将矩形作为创建工具，产出普通点线和显式关系，不额外引入
   隐式“矩形编辑状态”。若只写四点坐标，拖一个点即可变四边形，不算完整矩形能力。
3. **坐标、尺寸与约束谁驱动（点线已落实）。** 几何当前数据与独立约束分开。
   点坐标无论来自变量还是字面量，运行时语义相同；固定位置和驱动尺寸由显式约束
   决定。编辑器不覆盖表达式坐标；拖拽时从 AST 逐轴判断，把表达式轴锁在本次
   源码的求值（不是可能已被普通求解移动的显示位置）。`[width, 0]` 锁 X、可拖 Y。
   锁值改变几何时先满足这些锁与已有约束，再选第一个非拖动点作为临时锚点；
   初始未满足约束的数据在首次施加这些锁时可以调整。只回写可编辑轴的绝对解，
   对舍入后的实际源码数据做正向预览，保证与重编译使用相同输入，不追加表达式偏移。
4. **一条曲线裁成两条。** 不受影响的实体保留 ID。端点修剪的一对一变化和一分为二
   的歧义应分开处理；后者需要确认“退役旧 ID、给两段新 ID”还是“保留指定一段”。
   本地引用、尺寸和约束应在同一事务中更新或报告不能保留的关系，不能任意让下游
   旧引用指向其中一段。既定的无 `nextId` 策略保持不变，不以裁剪为由偷偷恢复它。
5. **派生时修剪上游。** 上游可作吸附/裁剪边界，但不能直接修改上游数组。是否提供
   显式派生裁剪/替换操作，或要求先创建本层几何，应单独决定；视觉上仍需区分所有权。
6. **面的身份。** 闭环顺序、填充区域下标和内核遍历顺序都不适合作为稳定公开 ID。
   区域分裂、合并和孔洞变化要有明确的引用决议；具体句柄/API 在建模出口阶段确认。

### 求解器边界

2026-09-06 已完成[第一轮隔离技术验证](sketch-solver-evaluation.md)：
现有 Ondsel 桥接与 PlaneGCS 的小规模几何检查在 Node / Chrome Worker 均通过。
用户已确认后端分工：刚体装配保留 OndselSolver，二维草图采用 PlaneGCS。
点线已接入固定版本 `@salusoft89/planegcs@1.2.0` 的原始 JS/WASM，直接使用
`GcsSystem`，不引入其 JSON 几何模型作为公开格式；装配继续保留 OndselSolver。

主分支已有 [`@code3d/solver`](../packages/solver/README.md)，使用 OndselSolver
处理刚体位姿及局部 marker 之间的关系。当前公开桥接并不直接接收任意 2D 点坐标、
圆半径和草图约束；“项目已有约束求解器”不等于“草图约束已经可用”。

P0 · B 的点线约束部分已实现：固定点、重合、水平/垂直、长度/角度、点 X/Y。
Node 与项目 Worker 加载同一固定依赖；每次求解独立创建并释放原生系统、点和诊断
向量，归一化并检查所有硬约束残差。冗余约束的 `Converged` 不直接当成功或失败，
以最终残差验收；冲突临时索引映射回源码。圆弧与其他曲线边界仍待后续实现。
持续预览和正常编译使用同一约束语义，GUI 不持有另一套持久求解结果。

## Lucide 接入

App 使用原生 JavaScript 包 `lucide`，首处接入是现有草图的选择、线、删除、
适配视图、吸附及绘制确认/取消按钮。保留明确按钮名称；SVG 仅作装饰，16px、`currentColor`、不可独立
聚焦且对辅助技术隐藏。公用 `ui/icon.ts` 承担这个显示契约，几何工具仍拥有行为。

按需具名导入并直接创建 SVG，不引入全量 `icons` 注册表或文档级替换扫描。
后续真实实现矩形、圆、剪刀时再添加相应图标，不提前摆放无行为按钮。品牌标记和
坐标 gizmo 是领域视觉，暂不改成通用图标。
依据：[Lucide 安装与按需导入](https://lucide.dev/guide/lucide/getting-started)、
[Lucide 可访问性](https://lucide.dev/guide/lucide/advanced/accessibility)。

## 第一套闭环的验收场景

- 空草图连续画线，用长度/角度输入，回到起点闭合；快速 Tab 不跳出页面，
  Escape 不留下半条线，源码撤销后 ID 和选择跟随恢复。
- 输入 40 × 30 创建矩形、创建半径 5 的圆；缩放后仍可精确吸附。尺寸可再次
  编辑，拖动后矩形保持直角，显示的参考尺寸与驱动尺寸不混淆。
- 剪掉交点之间的线段或圆弧，预览与实际结果一致；覆盖相切、重复交点、重叠线、
  闭合圆、极短段和大/小尺度。一次撤销同时恢复实体及相关约束。
- 以具名上游派生局部几何，修改上游坐标后引用仍正确；删除上游被引用点得到
  可定位错误，不自动引用另一个点。重编译不重排未变实体。
- 将带孔闭环转换为面并拉伸；开放线框、构造线、自交和多个区域有明确结果或诊断。
- 手写表达式、注释和无关 tuple 在工具更新后保留；保存、重载和 Node 执行所得
  几何一致。浏览器测试覆盖输入焦点、工具切换、派生编辑和源码来回编辑。
