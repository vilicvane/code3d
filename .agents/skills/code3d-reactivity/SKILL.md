# Code3D reactivity

采用 MobX 管理进程内状态与派生依赖，现有原生 DOM、Monaco 和 Three.js 消费状态。
先读取当前任务涉及的状态所有者与消费者，再决定迁移闭包；遵循
[持续重构原则](../code3d-prototyping/SKILL.md)，每次迁移完成一条真实联动链。
默认应用与 scope 约定见[项目级指令](../../../AGENTS.md#默认响应式迁移)。

## 状态、派生与操作

- 每份事实有一个所有者，通过命令修改，对外提供只读状态与查询。按项目、连接、
  工具会话等真实生命周期创建实例，不为联动建立全局大 store 或镜像状态。
- 用 `computed` 表达可以从当前事实算出的值；getter 保持纯计算。最后成功结果、
  曾经交互、用户选中的历史帧等历史事实仍是状态，不能误写成对当前结果的判断。
- `action` 批量发布一次同步变更；`await` 后的写入重新进入 action。外部事件和
  异步结果先核对所属请求/会话是否仍有效，再发布状态。
- 区分当前状态与逐次操作。连接在线状态、跟随目标、保存状态适合观察；重复的
  导航、提交、撤销等操作不能简单压成一个可被合并的“最新事件”observable。
  真正的操作通知可以保留，不能为了全项目使用 MobX 而丢失事件顺序或次数。
- 修改之前确认 lockfile 和已安装 MobX 的实际 API。使用显式 `makeObservable`
  标记涉及的字段、派生和命令；当前 MobX 7 的引用注解为 `observableRef` 等独立导出。
  纯状态模型可按证据选择自动注解；混合 DOM、连接和资源的对象不整体自动观察。
- 不变快照用引用观察；身份重要的集合用浅观察。不要深度转换协议配置、回执、
  Three.js、Monaco、Worker 或 WASM 对象。原生资源继续由所属服务显式创建和释放。

## 消费与生命周期

- UI 组件拥有自己的订阅及销毁；装配层只连接跨服务依赖。替换状态订阅时同步删除
  对应的手动 `refresh()`、转发回调和监听集合，不保留两条发布相同事实的路径。
- `reaction` 的数据函数读取依赖，副作用函数操作外部系统。纯渲染也可使用
  `autorun`，但它调用到的同步读取都会成为依赖。不能在渲染函数里修补共享状态。
- 能计算出的数据用 computed，不用 reaction 复制。生命周期变化可以触发明确命令，
  例如历史记录清空时结束浏览会话；这类转换有实际状态机语义，不是另一份派生值。
  不依赖多个 reaction 的隐含执行顺序；有顺序要求的步骤写在同一操作中。
- 状态同步提交；由消费者按需要选择同步、微任务或帧调度。回执写入不等待呈现，
  批量恢复可在视图侧合并；不要全局更改 reaction scheduler 来掩盖局部时序问题。
  延后执行的回调要在同步数据函数中先读取依赖，不能期待异步读取被追踪。
- 连接活跃度、帧选择、列表结构等不同依赖可以分开消费，防止轻量状态变化重建
  列表、抢焦点或重置滚动。对原生 DOM 保留有交互身份的节点，聚焦发生在节点更新后。
  表单输入保留未提交草稿，仅在对应已提交值变化时回填，避免无关状态刷新覆盖输入。
- 组件/会话结束时销毁 reaction、事件监听、定时任务和视图资源。已排队的呈现不得
  在销毁后恢复 UI；连接关闭与持久化收尾按自己的资源生命周期完成。

## 异步边界

MobX 不提供请求取消、文件系统事务或跨进程共享图。沿现有服务区分：

- 编译、补全等采用最新结果时，保留 revision/会话代次检查和底层取消机制。
- 文件写入、源码事务、授权持久化等需要顺序的命令保留队列。等待完成后发布成功；
  失败以真实保存结果恢复，不把 action 当数据库回滚。
- 页面/项目关闭后，旧恢复、连接回调与请求结果不能复活已结束的会话。仍在进行的
  写入先排空再关闭存储；创建多个资源时，失败也须收齐已创建的资源再释放。
- Worker、CLI 和其他进程传递普通数据及版本，各自维护状态与所有权；公开 Core
  建模 API 保持既定值语义，不因 App 状态迁移而引入另一套响应式建模语义。

## 自进化

本技能是当前证据支持的工作约定，后续相关开发应主动审查它是否仍然准确：

1. 在真实任务中发现更清楚的归属、更合适的调度或现有规则导致错误时，先定位原因，
   用实际行为或必要的回归验证判断；不把偶发失败或偏好直接升级成全局规范。
2. 同一任务内修订对应规则和受影响的实现/文档。优先改写、合并或删除旧规则，
   避免持续追加例外、兼容包装、经验流水或新的抽象层。
3. 技能保留能改变后续决策的原则与边界；具体 API、常量和验收输入由源码及测试
   维护。没有新证据时无需为了“自进化”机械修改技能。
4. 自进化不扩大任务、结构调整或外部操作的授权。新的用户决策优先；尚未确认的
   提案继续留在讨论中，不写成全项目必须执行的规范。

验证关注消费者可观察的结果：多处联动、派生一致性、重复操作、异步竞争、保存失败、
资源销毁与真实 DOM 交互；不要只验证字段被标记 observable。浏览器检查同时留意
MobX 在 console 中报告的 reaction 错误或 action 警告，因为它们未必成为 pageerror。

## 现有入口

- [AgentConnections](../../../packages/app/src/agent/connections.ts)：连接、授权、跟随、
  活跃度与资源生命周期；[AgentPanel](../../../packages/app/src/agent/panel.ts)消费这些状态。
- [AgentProjectSession](../../../packages/app/src/agent/project-session.ts)：保存队列、
  revision、未保存状态与逐次 Agent 操作通知。
- [AgentRenderHistory](../../../packages/app/src/agent/render-history.ts)及
  [AgentRenderView](../../../packages/app/src/ui/agent-renders.ts)：回执投影、呈现调度和图像资源。
- MobX [状态](https://mobx.js.org/observable-state.html)、
  [actions](https://mobx.js.org/actions.html)、[reactions](https://mobx.js.org/reactions.html)
  用于复查原理；API 与当前版本不一致时读取已安装包的声明和 changelog。
