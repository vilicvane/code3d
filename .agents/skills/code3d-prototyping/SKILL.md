# code3d prototyping

code3d 的项目代码始终保持在当前认知下可达到的最佳抽象和实现。原型阶段不是积累技术债的理由。

涉及坐标构造器、原点、空间变换、关系摆放或组合坐标转换时，同时读取 [code3d coordinate semantics](../code3d-coordinate-semantics/SKILL.md)，按模型局部坐标与相对位置的已确认语义设计和核对实现。

修改三维视口的辅助标记、高亮、关系方向或空间控件时，同时读取 [code3d visualization](../code3d-visualization/SKILL.md)，沿用已确认的尺寸、颜色和几何范围约定。

每次功能新增、修改或修复，都执行[项目级默认响应式迁移](../../../AGENTS.md#默认响应式迁移)，
使用[响应式技能](../code3d-reactivity/SKILL.md)界定相关 scope，并在同一任务中完成重构。

## Always refactor

- 每次改动都要把所涉及的职责及其真实依赖闭包重构到最佳终态；不能只补症状、绕过错误抽象，或把清理工作留给以后。
- 主路径中不保留已知技术债，包括临时桥接、重复实现、兼容分支、过时入口、死代码、泄漏的内部边界和没有明确外部阻碍的 TODO。
- 现有 API、示例、内部表示和运行时行为都不是天然约束。方向变化时迁移全部相关调用方、测试、示例、文档和工具，然后删除旧语义。
- 不添加 deprecated alias、兼容 wrapper、双轨语义或 fallback，除非用户明确要求，且给出了当前确实存在、无法在本次迁移的外部约束。
- 产品配置、协议与持久化结构的变更遵循[项目级原型期格式规则](../../../AGENTS.md#原型期格式版本)，按下述约定区分格式版本与内容修订。
- 不以最小 diff、短期开发速度或“只是 prototype”降低结构和实现质量。评价标准是终态是否统一、清楚、完整、可验证。
- “最佳”以当前需求和证据为准，不为假想未来堆叠抽象；但不能以避免扩大当前 diff 为由留下已经确认的结构问题。

## 格式版本

原型期不保留旧格式兼容路径、不得递增格式版本的约束，仅适用于 Code3D 产品
自身的配置、协议与持久化数据。仓库内部开发工作流工具（如 worktree 协调器）
的状态格式不受这两条约束，可按协作需要维护版本及迁移；不将其列为产品兼容性
问题清理。

允许保留 `version` 字段；原型期间其既定数字固定，不能把它作为功能或结构迭代
计数器。只提高数字并让读取端拒绝旧值，同样是格式版本升级，不因没有兼容分支
而变得允许。直接更新唯一现行结构、读写方和样例，删除旧格式迁移及兼容路径。

修改持久化字段时，沿序列化、解析、初始化、测试 fixture 和相关文档核对实际
写出的版本，不能只看本次新增代码。修正违规递增时保留仍有效的数据与用户选择，
不能因版本标记不同就把现有项目当成未初始化。用读写结果验证固定格式标记及
用户数据保留；不增加按旧版本分流的转换链。

npm 发布版本、依赖版本和防止覆盖修改的内容修订号不属于格式版本。托管目录的
内容指纹可随示例内容变化，项目清单的格式数字仍保持不变。

## Temporary work

- 只有明确隔离、可丢弃的探索代码、一次性诊断和临时测试探针可以降低长期维护要求。
- 临时代码不能进入公共 API、正常运行路径或持久模型格式，并应在得出结论后删除；只有用户明确要求保留时才能留下。
- 正式单元测试、集成测试、fixture 和测试基础设施属于项目代码，仍必须采用最佳可维护实现，不能借“测试代码”规避重构。
- 如果最佳抽象尚不清楚，先在隔离实验中验证；不要把尚未成立的临时设计接入主路径后再承诺未来清理。

## Semantic values without defensive programming

- 模型对象遵循语义不可变：正常作者 API 中的建模操作产生新值，不能改变旧值已经可观察到的模型语义。
- 语义不可变不要求 `Object.freeze()`、深拷贝或内部完全无 mutation。缓存、trace、惰性计算和 OpenCascade 资源生命周期可以在不改变作者可观察语义时使用 mutation。
- 默认信任项目内类型边界和工具可预见的正常调用方式。不要为正常路径无法触发的误用增加防御性复制、冻结、校验、fallback 或 impossible-state 分支。
- 只有正常作者代码或 GUI/tooling 确实可能产生该状态、错误需要在真实边界被解释，或输入来自明确的不可信外部边界时，才增加校验和恢复逻辑。
- 不得让防御性代码掩盖核心抽象、增加额外心智负担，或被误当成实现正确性的替代品。

## Work from current intent

- 修改核心语义前读取关联 GitHub issue、[设计原则](../../docs/design.md)，再从[开发文档索引](../../docs/README.md)选择相关架构专题。GitHub Issues 是需求、讨论、验收和进度的唯一跟踪入口；已移出的初期计划和需求通过索引中的固定历史链接追溯，不能作为当前开发规范或另一份 backlog。
- 一句话说清楚的需求直接作为 issue，不要求模板、固定章节或强制验收清单；agent 创建时记录已有的确定方案，维护时及时同步方案的确定与调整，并按实际需要补充上下文，不把填写工作交给用户。操作 issue 时读取 [GitHub Issues 协作约定](../worktree-development/references/github-issues.md)。
- 区分已确认决策与讨论中的假设。讨论提案、伪代码和候选 API 默认只留在对话中；除非用户明确要求记录或确认，不得将其提升为内部设计与架构专题的确定方向或其他规范性文档内容。
- 用户的新设计判断覆盖旧草稿和旧实现。发现两者冲突时先明确冲突，再按新判断重构。
- 修改过程中发现与当前职责直接相关的既有技术债时，将它纳入同一重构；无关区域仍不得借机扩张任务范围。
- 仍须保留用户拥有的工作区改动；“不保留产品兼容性”不等于可以覆盖或删除用户数据。

## Documentation

- 先区分修改 Code3D 源码的开发者与使用 Code3D 建模的用户/agent。仓库开发读取[内部文档](../../docs/README.md)的相关专题及本目录技能；建模 agent 的连接配置和 CLI 工作流不作为仓库开发流程。
- 对外再区分网站用户指南与建模 agent 操作说明。用户指南介绍连接、协作、跟随、观察和权限等概念；不要塞入完整 CLI payload、恢复协议或实现细节。建模 agent 从 [纯 Markdown 入口](../../../docs/agents.md) 开始，不依赖网页布局或交互组件。
- 建模 agent 文档保持两层：入口是必读的最小可执行工作流，读完能连接、获取现场上下文、读取和修改文件、观察结果；[专题](../../../docs/agents/) 展开具体功能、高级用法和异常恢复。入口列出完整专题目录，并简要介绍对建模有用的包；不罗列全部 workspace 或底层依赖。专题按任务需要互相链接。
- agent 文档与包 README 的相对链接指向真实仓库文件。通过 [网站 Markdown 发布器](../../../packages/web/scripts/markdown-documents.mjs) 映射为可直接读取的相对 Markdown 链接或对应提交的源码链接；发布产物在提交后构建并确保该提交已推送。技术指南与可执行示例共用现有源文件，不手工维护第二份镜像。新增 MDX 组件时同时提供它的纯 Markdown 表达。
- 网站 packages 文档只发布少数主推建模包，当前为 Core、Materials、Screws，由发布器的 `featuredPackages` 显式选择。底层包让 agent 沿 `package.json` 依赖在 GitHub 或已安装的 `node_modules` 中查阅 README，不自动镜像或加入入口目录。
- 所有自维护包（含 private App/Web）仍提供人和 agent 共用的 README：说明职责、适用入口、最小示例或启动方式，并链接公共类型、源码、测试和完整示例。包的使用说明与内部架构各按职责维护，README 将贡献者引向相关内部专题和代码，不重复维护完整架构或另建 agent 专用包 README。内部文档及研究记录沿仓库链接查阅，不因 README 引用而自动发布到网站。
- 修改 agent 操作、连接、配置或公开建模 API 时，在同一任务更新受影响专题、示例、包 README 与入口目录。只有必读规则或首次可执行流程改变时才增加入口内容；高级细节保留在专题。文档描述唯一现行语义，不保留旧命令或兼容路线。
- App 复制的初始和更新 prompt 只提供任务/身份、私有配置和必读 Markdown 入口。默认 agent 先读文档，服务启动、获取实时上下文的演示及操作规则统一放在入口和专题中，不在 prompt 重复，也不把现场上下文固化进 prompt。
- 验证 prompt → 入口 → 专题 → README → 源码/示例整条链路。文档发布改动须运行网站构建的 Markdown/HTML 链接与锚点检查；涉及 prompt 时验证实际复制出来的 URL，并在本地启动其指向的网站。开发 URL 与可选部署 base 路径遵循 [Web README](../../../packages/web/README.md#agent-documentation-and-local-prompts)。

## Handoff

说明最终保留的唯一语义、完成了哪些必要重构、删除了哪些旧路径，以及仍未决定的设计问题。不能把已知技术债包装成“后续优化”交付。
