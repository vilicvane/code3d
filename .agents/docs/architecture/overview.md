# 架构概览

Code3D 的作者文件是普通 TypeScript 项目。App 把文件、依赖和源码范围交给编译
Worker；Worker 使用项目选定的 Core 求值，再把可序列化快照交给视口和交互工具。
GUI 修改经过源码事务写回同一项目，下一次正常求值产生新的结果。

## 包边界

| 包                 | 职责与实现入口                                                                                                                                                     |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Core               | [作者 API](../../../packages/core/src/library/index.ts)、几何与关系语义；[tooling](../../../packages/core/src/tooling/index.ts)提供求值、trace、快照和内核安装集成 |
| OpenCascade        | [固定内核构建](../../../packages/opencascade/README.md)及其加载器、WASM 和来源记录                                                                                 |
| Screws / Materials | 使用公开 Core 入口实现可复用模型与材质；共享选定的 Core 和 Three.js 实例                                                                                           |
| App                | [项目适配](../../../packages/app/src/project/)、[编译和快照](../../../packages/app/src/model/)、编辑器、工具与视口                                                 |
| Agent / CLI        | [连接协议及桥接](../../../packages/agent/README.md)与[命令行客户端](../../../packages/cli/README.md)；App 拥有真实项目、源码修改与模型观察                         |
| Web                | [官网和文档发布](../../../packages/web/README.md)，组合独立 App 构建产物                                                                                           |
| Solver             | 独立的 [OndselSolver 包](../../../packages/solver/README.md)；当前 Core/App 的关系求解不加载它，草图使用 PlaneGCS                                                  |

Core root 只公开作者建模 API。`@code3d/core/tooling` 服务 App 集成，不能因为 App
需要某个内部字段就把它加入作者类型。公开签名涉及的命名类型须从相应入口导出。
更多边界见[建模内核](modeling.md)。

## App 响应式状态

App 使用 MobX 连接有明确所有者的状态与原生视图。Agent 的
[连接模型](../../../packages/app/src/agent/connections.ts)拥有授权、在线状态、跟随目标
和连接资源；面板、渲染历史视图及应用的跟随流程直接消费同一实例。
项目会话发布 revision 与未保存状态，逐次导航/提交通知仍是操作事件。
渲染历史是持久回执的内存投影，由视图合并呈现，不把 DOM 更新嵌入回执写入。

UI 组件释放自己的订阅，项目关闭时由连接模型排空在途操作后释放存储。
源码版本校验、保存队列与编译取消继续由原服务承担。响应式重构与自进化遵循
[响应式技能](../../skills/code3d-reactivity/SKILL.md)。

## 一次编辑的路径

1. 项目层合并磁盘内容与未保存源码，语言服务按需准备对应类型环境。
2. 编译层分析当前入口、模型调用、参数与源码位置，构建可执行的源模块图。
3. 选定运行时复用依赖和内核，源码在新的求值上下文中执行。
4. trace 和快照保留当前源码目标、操作输入、模型实例、拓扑及组合位姿；独立
   快照 Worker 负责可并行的几何查询。
5. 视口显示当前关注范围，工具把交互变成有版本和 expected text 校验的源码修改。
6. 新编辑取消旧请求，旧求值按完整操作边界收尾；只接受当前 revision 的结果。

类型读取不执行 Core，渲染层不反推作者的构建步骤。依赖实例、源码求值、几何
缓存与显示快照各有生命周期，不能用同一个缓存键或清理策略替代它们。
