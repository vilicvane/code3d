# 设计原则

Code3D 将普通 TypeScript 建模与直接几何交互连接起来。模型作者可以使用函数、
模块、控制流和 npm 包，GUI 为代码中不直观的空间操作提供补充。

## 源码与模型

- 源文件是模型持久化状态的唯一来源。GUI 的预览是临时状态，确认后的修改写回源码，
  撤销复用编辑器历史；不维护另一份可独立编辑的模型文档或特征树。
- 关注模型值及其关系。任何源码文件都可成为执行入口，任意产生模型的表达式都可
  被检查；不要求固定入口函数或 export。导出用于复用和发布。
- 模型遵循语义不可变的值语义。建模操作产生新值，旧模型及其引用的可观察结果
  不被后续操作改变。内部缓存和共享原生资源服从这个边界。
- 模型项目沿用标准 TypeScript、ESM 和包结构。类型分析和运行时执行读取同一个
  项目依赖环境；浏览器能力边界通过明确诊断表达。

## 交互

- 模型编辑以代码为主，GUI 补充空间操作；信息展示可更充分使用 GUI。
  草图仍由源码持久化，但点线绘制和编辑以可视化为主。
- 交互有明确的源码、运行实例、操作及几何范围。同一表达式的多次求值不能被混为
  一个可任意修改的实例；修改共享源码自然影响其全部求值。
- 参数追踪必须找到唯一、安全的源码目标。不能反向编辑的表达式不被暗中替换成
  求值后的常量；需要替换表达式时由明确的编辑操作完成。
- GUI 所见预览与提交后正常源码求值应一致。诊断、取消、旧快照及只读状态显式区分，
  不用隐藏约束或第二套求值规则弥补不一致。
- 模型局部坐标、组合位姿及几何参考架各有归属。摆放、原点和几何变换保持清楚的
  语义；拓扑身份表达来源，不依赖内核瞬时句柄或数组位置。

## 运行与复用

- 普通编辑重新求值源码，复用未变化的依赖与完整几何计算。缓存不能携带过期的源码
  位置、交互状态或运行实例身份。
- 零安装建模与项目自行安装 Core 都是明确支持的模式。项目声明自己的 Core 后，
  缺失或不兼容的安装应报错；类型、执行和导出使用同一个选定运行时。
- 模型库、模型工具和常用材质通过普通包复用。公开作者 API 与 App 集成接口分开，
  但不复制内核、类型声明或材质类实例来连接它们。
- Worker 隔离耗时执行并支持取消；缓存和持久存储失效不应破坏作者文件。
  Worker 并非任意不可信代码的安全沙箱。

## 非目标

- 复刻完整的传统 CAD 工作流，或把构建历史作为作者必须操纵的主要抽象。
- 为 GUI 同步限制 JavaScript/TypeScript 的表达能力，或反向求解任意程序。
- 让作者模型直接暴露 OpenCascade 句柄，或由作者操纵 App 的 Three.js 场景对象。
  原生材质可以作为值输入，显示实例由渲染层管理。
- 将原型内部格式和集成协议版本化，以维持多套并行语义。
